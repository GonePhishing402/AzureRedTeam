# Defend Azure Container Apps — Logging, Monitoring & Defender for Cloud

A guide for configuring Azure Container Apps diagnostic logging to a Log Analytics Workspace, investigating activity using KQL, and leveraging Microsoft Defender for Containers alerts.

---

## 1. Enable Diagnostic Logging

Azure Container Apps supports three logging destinations configured at the **environment** level:

| Destination | Description |
|---|---|
| **Log Analytics** | Logs stored directly in a Log Analytics workspace (default) |
| **Azure Monitor** | Logs routed via diagnostic settings to LA, Storage, Event Hub, or partner solutions |
| **None** | Logging disabled (real-time log stream still available) |

### Azure Portal

1. Navigate to your **Container Apps Environment** in the [Azure Portal](https://portal.azure.com)
2. Select **Monitoring** > **Logging options**
3. Set **Logs Destination** to **Azure Log Analytics** or **Azure Monitor**
4. If using **Azure Monitor**, configure Diagnostic Settings (see below)
5. Select **Save**

#### Configure Diagnostic Settings (Environment Level)

1. Navigate to your **Container Apps Environment**
2. Select **Monitoring** > **Diagnostic settings**
3. Select **+ Add diagnostic setting**
4. Enter a name for the setting
5. Under **Logs**, select the categories to capture (e.g., `ContainerAppConsoleLogs`, `ContainerAppSystemLogs`)
6. Under **Destination details**, select **Send to Log Analytics workspace**
7. Select your workspace and click **Save**

#### Configure Diagnostic Settings (Container App Level)

1. Navigate to your **Container App**
2. Select **Monitoring** > **Diagnostic settings**
3. Select **+ Add diagnostic setting**
4. Under **Metrics**, select **AllMetrics**
5. Select destination and click **Save**

### Azure CLI

```bash
# Register the Microsoft.Insights namespace
az provider register --namespace Microsoft.Insights

# Create a Log Analytics Workspace (if one doesn't exist)
az monitor log-analytics workspace create \
  --resource-group <resource-group> \
  --workspace-name <workspace-name>

# Option 1: Create environment with Log Analytics destination (default)
az containerapp env create \
  --name <ENVIRONMENT_NAME> \
  --resource-group <RESOURCE_GROUP_NAME> \
  --logs-destination log-analytics \
  --logs-workspace-id <LOG_ANALYTICS_WORKSPACE_ID>

# Option 2: Update existing environment to use Azure Monitor
az containerapp env update \
  --name <ENVIRONMENT_NAME> \
  --resource-group <RESOURCE_GROUP_NAME> \
  --logs-destination azure-monitor

# Create diagnostic settings at the environment level (all logs + metrics)
az monitor diagnostic-settings create \
  --name "ContainerAppsDiagnostics" \
  --resource <ENVIRONMENT_ID> \
  --logs '[{"categoryGroup":"allLogs","enabled":true}]' \
  --metrics '[{"category":"AllMetrics","enabled":true}]' \
  --workspace <LOG_ANALYTICS_RESOURCE_ID>

# Create diagnostic settings at the container app level (metrics only)
az monitor diagnostic-settings create \
  --name "ContainerAppMetrics" \
  --resource <CONTAINER_APP_ID> \
  --metrics '[{"category":"AllMetrics","enabled":true}]' \
  --workspace <LOG_ANALYTICS_RESOURCE_ID>
```

### PowerShell

```powershell
# Get the Container Apps environment resource ID
$environmentId = (Get-AzContainerAppManagedEnv -ResourceGroupName <resource-group> -Name <env-name>).Id

# Get the Log Analytics workspace resource ID
$workspaceId = (Get-AzOperationalInsightsWorkspace -ResourceGroupName <resource-group> -Name <workspace-name>).ResourceId

# Create diagnostic setting – all logs and metrics to Log Analytics
$log = New-AzDiagnosticSettingLogSettingsObject -CategoryGroup "allLogs" -Enabled $true
$metric = New-AzDiagnosticSettingMetricSettingsObject -Category "AllMetrics" -Enabled $true

New-AzDiagnosticSetting -Name "ContainerAppsDiagnostics" `
  -ResourceId $environmentId `
  -Log $log `
  -Metric $metric `
  -WorkspaceId $workspaceId
```

## 2. Log Analytics Tables

When using **Log Analytics** as the destination, tables use the `_CL` suffix. When using **Azure Monitor** diagnostic settings, tables do **not** include the suffix.

### Log Analytics Destination Tables

| Table | Description |
|---|---|
| `ContainerAppConsoleLogs_CL` | Container `stdout` and `stderr` output (application logs) |
| `ContainerAppSystemLogs_CL` | System logs generated by the Container Apps service (revisions, Dapr, auth, traffic) |

### Azure Monitor Destination Tables

| Table | Description |
|---|---|
| `ContainerAppConsoleLogs` | Console logs (no `_CL` suffix) |
| `ContainerAppSystemLogs` | System logs (no `_CL` suffix) |

### Key Columns in ContainerAppConsoleLogs_CL

| Column | Description |
|---|---|
| `ContainerAppName_s` | Container app name |
| `ContainerGroupName_g` | Replica name |
| `ContainerId_s` | Container identifier |
| `ContainerImage_s` | Container image name |
| `EnvironmentName_s` | Container Apps environment name |
| `Log_s` | Log message |
| `RevisionName_s` | Revision name |

### Key Columns in ContainerAppSystemLogs_CL

| Column | Description |
|---|---|
| `ContainerAppName_s` | Container app name |
| `EnvironmentName_s` | Container Apps environment name |
| `Log_s` | Log message |
| `RevisionName_s` | Revision name |

### Session Pool Tables (Custom Container Sessions)

| Table | Description |
|---|---|
| `AppEnvSessionConsoleLogs` | Session container `stdout`/`stderr` output |
| `AppEnvSessionLifecycleLogs` | Session lifecycle events (allocation, state changes) |
| `AppEnvSessionPoolEvents` | Session pool operational events |

## 3. KQL Investigation Queries

### Recent Console Logs (All Apps)

```kusto
ContainerAppConsoleLogs_CL
| where TimeGenerated > ago(1h)
| project Time=TimeGenerated, AppName=ContainerAppName_s, Revision=RevisionName_s, Container=ContainerName_s, Message=Log_s
| order by Time desc
| take 100
```

### System Logs for a Specific Container App

```kusto
ContainerAppSystemLogs_CL
| where ContainerAppName_s == '<container_app_name>'
| project Time=TimeGenerated, EnvName=EnvironmentName_s, AppName=ContainerAppName_s, Revision=RevisionName_s, Message=Log_s
| order by Time desc
| take 100
```

### Detect Revision Provisioning Errors

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "Error provisioning revision"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Revision=RevisionName_s, Message=Log_s
| order by Time desc
```

### Detect `exec` Session Activity (Red Team Indicator)

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "exec" or Log_s contains "getauthtoken"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Message=Log_s
| order by Time desc
```

### Detect Suspicious stderr Output (Errors / Tool Output)

```kusto
ContainerAppConsoleLogs_CL
| where Log_s contains "error" or Log_s contains "exception" or Log_s contains "unauthorized"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Container=ContainerName_s, Image=ContainerImage_s, Message=Log_s
| order by Time desc
| take 200
```

### Detect Container Image Changes (Backdoor / Image Swap)

```kusto
ContainerAppConsoleLogs_CL
| summarize Images=make_set(ContainerImage_s) by ContainerAppName_s
| where array_length(Images) > 1
```

### Detect Authentication Config Changes

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "Auth" or Log_s contains "authentication"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Message=Log_s
| order by Time desc
```

### Detect Traffic Weight Changes (Revision Shifting)

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "traffic weight"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Revision=RevisionName_s, Message=Log_s
| order by Time desc
```

### Detect Dapr Component Errors

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "dapr" and Log_s contains "Error"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Message=Log_s
| order by Time desc
```

### Volume Mount Events

```kusto
ContainerAppSystemLogs_CL
| where Log_s contains "volume" or Log_s contains "mount"
| project Time=TimeGenerated, AppName=ContainerAppName_s, Revision=RevisionName_s, Message=Log_s
| order by Time desc
```

## 4. Recommended Alert Rules

| Alert | Condition | Severity |
|---|---|---|
| **Revision Provisioning Failure** | `ContainerAppSystemLogs_CL` where `Log_s contains "Error provisioning"` | High |
| **Image Pull Error** | `ContainerAppSystemLogs_CL` where `Log_s contains "ErrImagePull"` | High |
| **Container Crashing** | `ContainerAppSystemLogs_CL` where `Log_s contains "ContainerCrashing"` | Critical |
| **Unexpected Auth Config Change** | `ContainerAppSystemLogs_CL` where `Log_s contains "Auth config"` | Medium |
| **Traffic Weight Shift** | `ContainerAppSystemLogs_CL` where `Log_s contains "traffic weight"` | Medium |
| **Multiple Container Images per App** | `ContainerAppConsoleLogs_CL` summarize distinct images > 1 | Medium |
| **Excessive stderr Output** | `ContainerAppConsoleLogs_CL` where error count > threshold | Low |

## 5. Microsoft Defender for Containers

Azure Container Apps workloads are covered by **Microsoft Defender for Containers**, which provides runtime threat protection, vulnerability assessment, and security posture management across containerized environments.

### Enabling Defender for Containers

1. Navigate to **Microsoft Defender for Cloud** in the [Azure Portal](https://portal.azure.com)
2. Select **Environment settings** > your subscription
3. Enable **Defender for Containers**
4. The Defender sensor deploys automatically via the AKS Resource Provider

### MITRE ATT&CK Coverage

Defender for Containers maps detections to the **MITRE ATT&CK for Containers** framework, covering tactics such as:

| Tactic | Examples |
|---|---|
| **Initial Access** | Exposed Kubernetes dashboards, risky service exposures |
| **Execution** | Web shell activity, suspicious process execution |
| **Persistence** | Creation of high privileged roles, sensitive mounts |
| **Privilege Escalation** | Privileged container deployments |
| **Defense Evasion** | Binary drift detection (executing binaries not in original image) |
| **Credential Access** | Access to cloud metadata service, secret reconnaissance |
| **Discovery** | Network scanning tools, suspicious service account operations |
| **Impact** | Crypto mining activity, CPU optimization abuse |

### Control Plane Detection

Defender monitors the Kubernetes API server for:

- Privileged container deployments
- Risky service exposures to the public internet
- Suspicious service account activities (excessive resource requests, unauthorized API calls)

### Workload Runtime Detection

The Defender sensor monitors runtime activity for:

- **Web shell activity** — behaviors resembling web shell invocations
- **Crypto mining** — suspicious downloads, CPU optimization, suspicious process execution
- **Network scanning tools** — usage of scanning tools with known malicious patterns
- **Binary drift** — execution of binaries not present in the original container image

### Key Defender for Containers Alerts

| Alert | MITRE Tactic | Description |
|---|---|---|
| **Possible Web Shell activity detected** | Execution | Web shell invocation behavior in a container |
| **Suspicious Kubernetes service account operation** | Discovery | Unusual service account activity detected |
| **Network scanning tool detected** | Discovery | Known scanning tool observed in a container |
| **Privileged container detected** | Privilege Escalation | A container running with elevated privileges |
| **Exposed Kubernetes dashboard** | Initial Access | Publicly accessible Kubernetes dashboard |
| **Access to cloud metadata service detected** | Credential Access | Attempt to reach cloud instance metadata |
| **Sensitive files access detected** | Credential Access | Access to sensitive files (keys, tokens) |
| **Possible secret reconnaissance detected** | Credential Access | Enumeration of secrets in the cluster |
| **Kubernetes CPU optimization detected** | Impact | CPU resource optimization (mining indicator) |
| **Possible Crypto miners download detected** | Impact | Download of known crypto mining software |
| **A drift binary detected executing in the container** | Defense Evasion | Binary not in original image executing |
| **Creation of high privileged role detected** | Persistence | New high-privilege Kubernetes role created |

### Simulation Tool

Microsoft provides an alert simulation tool to test Defender for Containers detections:

```bash
# Download the simulation tool
curl -O https://raw.githubusercontent.com/microsoft/Defender-for-Cloud-Attack-Simulation/refs/heads/main/simulation.py

# Prerequisites: kubeconfig pointed at target cluster, Helm, Python 3.7+
# Verify Defender sensor is installed
kubectl get ds microsoft-defender-collector-ds -n kube-system

# Run the simulation
python simulation.py
```

**Simulation Scenarios & Expected Alerts:**

| Scenario | Expected Alerts |
|---|---|
| **Reconnaissance** | Web Shell activity, Suspicious K8s service account operation, Network scanning tool |
| **Lateral Movement** | Web Shell activity, Access to cloud metadata service |
| **Secrets Gathering** | Web Shell activity, Sensitive files access, Secret reconnaissance |
| **Crypto Mining** | Web Shell activity, CPU optimization, `ld.so.preload` access, Crypto miner download, Drift binary |
| **Web Shell** | Web Shell activity |

### Response Workflow

1. **Triage** — Review alert in Defender for Cloud or Microsoft Defender XDR portal
2. **Investigate** — Use the incident graph to trace pod/service/cluster entities
3. **Contain** — Isolate or terminate compromised container pods directly from XDR
4. **Remediate** — Redeploy from known-good images, rotate exposed secrets
5. **Harden** — Review attack paths in Defender for Cloud and close gaps
